# Signal Store — Financial Exchange Architecture & Engineering Standards

Добро пожаловать в репозиторий торговой платформы / биржи **Signal Store**.
Проект построен на базе **Nx Monorepo**, **Angular (версия 22+)** и строгого реактивного подхода на **Angular Signals**.

---

## 🏛 1. Архитектурные принципы

### Модульность и Слои (Nx Architecture)

1. **`apps/`**: Точки входа приложений (например, `apps/exchange`). Содержат только конфигурацию, корневой роутинг и инициализацию.
2. **`libs/`**: Вся бизнес-логика разделена по доменам:
   - `data-access`: Signal Stores, WebSocket клиенты, REST API сервисы, модели данных и DTO.
   - `feature-*`: Страницы, умные компоненты (smart/container), координирующие пользовательские сценарии (OrderBook, Trading, Positions, DepthChart).
   - `ui-*`: Презентационные (dumb) компоненты, кнопки, бейджи, инпуты, стаканы цен без сайд-эффектов.
   - `util-*`: Чистые функции, математика фиксированной точки (Decimal math), форматирование валют, хелперы сигналов.

## ⚡ 2. Стандарты Angular & Signals

- **Signal-First Reactivity**:
  - Используем `signal()`, `computed()`, `effect()`, `linkedSignal()` и `resource()`.
  - Избегаем устаревших RxJS паттернов там, где данные синхронны или декларативны.
  - RxJS используется исключительно для высокочастотных потоков событий (WebSocket тики, стримы стакана заявок) с последующим преобразованием в сигналы через `toSignal()`.
- **Change Detection**:
  - Все компоненты работают в режиме **OnPush по умолчанию** (в Angular 22+ OnPush включен по умолчанию, явное указание `changeDetection: ChangeDetectionStrategy.OnPush` не требуется).
  - Никаких грязных мутаций объектов: стейт всегда иммутабелен через `.update()` или `structuredClone()`.
- **Dependency Injection**:
  - Использовать `inject(...)` вместо громоздких конструкторов.
- **Standalone Only**:
  - Никаких `NgModule`. Все компоненты, пайпы и директивы standalone.
- **Accessibility & CDK**:
  - Использовать `@angular/cdk/a11y` и примитивы CDK (Virtual Scrolling для стакана цен и ленты сделок, FocusTrap для модалок, KeyEvents для горячих клавиш трейдинга).

## 💰 3. Требования к финансовой точности и производительности

1. **Точность чисел (Precision & Rounding)**:
   - Никогда не использовать стандартную арифметику с плавающей точкой (`0.1 + 0.2 === 0.30000000000000004`) для расчёта балансов и сумм сделок.
   - Использовать `BigInt`, строковые представления или специализированные функции для Decimal-вычислений.
2. **Высокая частота обновлений (Market Data & OrderBook)**:
   - Ограничивать частоту перерендеринга тикеров через буферизацию (throttling / batching RAF).
   - Для глубоких стаканов заявок (OrderBook Depth) применять `cdk-virtual-scroll-viewport` либо мемоизированные `computed()`.
3. **Безопасность и валидация ордеров**:
   - Строгая валидация входных данных: тип ордера (Market, Limit, Stop-Limit), цена (Tick Size), объем (Lot Size), Time-in-Force (GTC, IOC, FOK).

## 🧹 4. Линтинг, Форматирование и Чистота Кода

- **Prettier**: Настроен `prettier-plugin-organize-imports` для автоматического удаления неиспользуемых импортов и их упорядочивания при сохранении/форматировании (`npm run format`).
- **ESLint**: Настроены `@angular-eslint` и `eslint-plugin-unused-imports`.
- **Скилл `cc`**: Перед коммитом или сдачей задачи всегда используйте скилл `cc` для контроля качества, проверки чистоты кода и формирования коммита по Conventional Commits.
